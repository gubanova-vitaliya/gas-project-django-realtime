# Настройка HTTPS для локальной разработки

Для работы PWA на мобильных устройствах необходимо использовать HTTPS. В продакшене (GitHub Pages) HTTPS работает автоматически, но для локальной разработки нужно настроить локальный сертификат.

## Установка mkcert

Сначала установите `mkcert` глобально:

```bash
npm install -g mkcert
```

**Примечание:** На Windows может потребоваться запустить PowerShell от имени администратора.

## Создание сертификатов

### Шаг 1: Создание Certificate Authority (CA)

Создайте локальный Certificate Authority, который будет подтверждать ваш сертификат:

```bash
mkcert create-ca
```

Эта команда создаст два файла:
- `ca.crt` - публичный ключ Authority
- `ca.key` - приватный ключ Authority

### Шаг 2: Создание сертификата

Создайте сам сертификат для вашего приложения:

```bash
mkcert create-cert
```

Эта команда создаст два файла:
- `cert.crt` - публичный ключ сертификата
- `cert.key` - приватный ключ сертификата

### Итого должно быть 4 файла:

```
gase-frontend/
├── ca.crt      (публичный ключ Authority)
├── ca.key      (приватный ключ Authority) ⚠️ НЕ ПУБЛИКУЙТЕ!
├── cert.crt    (публичный ключ сертификата)
└── cert.key    (приватный ключ сертификата) ⚠️ НЕ ПУБЛИКУЙТЕ!
```

## ⚠️ ВАЖНО: Безопасность

**НИКОГДА не выкладывайте приватные ключи в общий доступ, даже на GitHub!**

Все файлы с расширениями `.key` и `.crt` уже добавлены в `.gitignore`, но убедитесь, что они не попали в репозиторий:

```bash
# Проверьте, что файлы не отслеживаются Git
git status

# Если файлы уже были добавлены, удалите их из индекса:
git rm --cached ca.key cert.key ca.crt cert.crt
```

## Настройка браузера

После создания сертификатов, браузер может показать предупреждение о безопасности. Это нормально для локальных сертификатов.

### Chrome/Edge:
1. Откройте `chrome://settings/security` или `edge://settings/privacy`
2. Прокрутите до "Manage certificates"
3. Импортируйте `ca.crt` в "Trusted Root Certification Authorities"

### Firefox:
1. Откройте `about:preferences#privacy`
2. Прокрутите до "Certificates"
3. Нажмите "View Certificates" → "Authorities" → "Import"
4. Выберите `ca.crt` и отметьте "Trust this CA to identify websites"

## Запуск приложения с HTTPS

После создания сертификатов, просто запустите приложение:

```bash
npm run dev
```

Приложение будет доступно по адресу:
- `https://localhost:3000` - на локальной машине
- `https://YOUR_IP:3000` - с других устройств в той же сети

Где `YOUR_IP` - это IP-адрес вашего компьютера:
- **Windows:** `ipconfig` (ищите IPv4 адрес)
- **Linux/Mac:** `ip addr` или `ifconfig` (ищите inet адрес)

## Проверка работы HTTPS

1. Откройте приложение в браузере по HTTPS адресу
2. Откройте DevTools (F12) → Application → Service Workers
3. Service Worker должен быть зарегистрирован и активен
4. На мобильном устройстве в той же сети откройте приложение по IP-адресу
5. PWA должно работать корректно

## Устранение проблем

### Ошибка: "Cannot find module 'cert.key' or 'cert.crt'"

**Решение:** Убедитесь, что вы создали сертификаты командой `mkcert create-cert` в корне проекта `gase-frontend/`

### Браузер показывает предупреждение о безопасности

**Решение:** Импортируйте `ca.crt` в доверенные сертификаты браузера (см. раздел "Настройка браузера")

### Service Worker не работает на мобильном устройстве

**Решение:** 
1. Убедитесь, что вы открываете приложение по HTTPS (не HTTP)
2. Убедитесь, что используете IP-адрес, а не localhost
3. Проверьте, что мобильное устройство в той же сети

### Ошибка: "The script has an unsupported MIME type"

**Решение:** Это происходит при использовании HTTP вместо HTTPS. Убедитесь, что:
- Сертификаты созданы правильно
- Приложение запущено и доступно по HTTPS
- В адресной строке указан `https://`, а не `http://`

## Альтернатива: Использование vite-plugin-mkcert

Если вы не хотите создавать сертификаты вручную, `vite-plugin-mkcert` может автоматически создавать их. Однако для работы с мобильными устройствами рекомендуется использовать ручной способ, описанный выше.
